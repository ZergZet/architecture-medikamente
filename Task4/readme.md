# Задание 4. Оценка узких мест при миграции

Основаная цель миграции — постепенно перейти от разрозненного ландшафта к расширяемой сервисной архитектуре без прерывания основной деятельности и без потерей контроля над обрабатываемими чувствительными данными.

## 1. Первостепенные задачи

1. Провести первичную инвентаризацию и классификацию и разделение данных по доменам.
2. Обеспечить защиту периметра от утечки классифицированных данных (DLP)
3. Обеспечить перенос в защищённые(шифрование+ KMS) хранилища в соответствии с проведённой классификаций, разграничением доступа (IAM).
4. Поскольку данные продолжают поступать, обеспечить возможность непрерывного привычный доступа как к историческим данным, так и к добавляемой информации (NextCloud с СУБД и S3 вместо Excel и папок c со сканами).
5. Обеспечить возможность выполенния процедуры прекращения обработки и удаление ПДн.
6. Подготовить резервное копирование и проверить восстановление.
7. Разработать порядок миграции, отката и поддержки.
8. Расcчитать и подготовить оборудование для обеспечение отказоустойчивости и учеличенную нагрузку.
9. Выделить тестовую среду для проверки решений перед развёртыванием .
10. Провести обучение по безопасности и конфигурировании микросервисной инфраструктуры (предъявлять требования кандидатам при расширеннии штата).   
11. Обеспечить сбор событий безопаности и доступа к данным (SIEM)

## 2. Задачи второй очереди

1. Перед масштабированием обеспечить обеспечить мониторинг загрузки и расходования ресурсов (Victoria Metrics, Grafana, уведомления).
2. Формализовать и утвердить спецификацию API взвимодействия с лабораторией.
3. Внедрение CI/CD и quality gates для минимизации ошибок.
4. Обеспечить постепенную миграцию по доменам на новую архитектуру с глубоким структурированием и преобразование данных.
6. Обеспечить масштабирование критичных сервисов API шлюза и балансировщика нагрузки.

## 3. Задачи третьей  очереди
1. Разделяем членов команды по ролям и специализациям для разработчики, внедрение, поддержку и администрирование, обеспечения безопасноти.
2. Запланировать обучение сотрудников новым процессам и инструментам.
3. Расширить аналитику до полноценного Data Lake.
2. Полностью автоматизировать классификацию новых двнных и старых файлов через DLP/OCR.
3. Реализовать зрелый Data Lineage.
4. Автоматизация сценариев аварийного восстановления, проведение регулярных проверок на отказ.
5. Добавить распределённую трассировку и бизнес-метрики для расширенного контроля миграции.

## Заключение

Ключевые риски миграции связаны с производительностью оборудования, качеством данных, правами доступа, интеграциями
ручными процессами и незрелостью эксплуатационных процессов. 
Поэтому стратегия миграции должна быть поэтапной, с ранним внедрением контуров безопасности,  резервным копированием, аудитом и с ростом нагрузки постоянной проверкой результатов по метрикам.
