

## 1. Конфиденциальные данные, которые не учтены во внутренних системах.
### Анализ информации о компании.

Ключевая информация по безопасности данных: 
1. Внутренние потоки данных между IT-продуктами никак не контролируются. 
2. IT-системах без аудита действий.
3. Любой бизнес-процесс в компании сопровождается обращением к конфиденциальным данным разного уровня.
4. Локальные способы хранения данных на рабочих местах пользователей.
5. Со стороны систем обработки нет ограничений на доступ к данным.
6. Совместно обрабатывает персональные, медицинские, финансовые данные и документы.

В системе обрабатываются и хранятся следующие типы данных:
1. персональные данные: Ф. И. О., дату рождения, телефон и электронную почту
2. персональные данные (расширенные): адрес прописки, месте работы или учёбы. 
3. Медицинские данные (также ПДн):  хронических заболеваниях, результаты анализов, диагнозы, назначения,  история болезней, заключения врачей, записи к врачу.
4. Финансовые данные: данные оплат, данные договоров, история платежей, зарплатные данные, кадровые данные, налоговые данные
5. Учётные данные: данные товарно-материальных ценностей
6. Промежуточные данные для построения отчётов, включающие информацию по всем обрабатываемым данным.

4. Приём и учёт платежей пациентов

7. Построение аналитических отчётов работы компании

## 2. Аудит мер по обеспечению безопасности данных.

### Сопосталение процессов в компании с требованиями по обеспечению безопасности данных и архитектурными практиками в области безопасности конфиденциальных данных.
#### **Privacy by Design** в полной мере не выполняется ни один из 7 принципов.
1. Проактивный, а не реактивный; превентивный, а не только устранение последствий 
    - Оценка рисков, выявление и оценка потенциальных рисков конфиденциальности на этапе планирования не проводилась.
    - Не проводится оценка воздействия на частную жизнь, систематическое изучение того, как обрабатываются персональные данные, для обеспечения соответствия и выявления рисков.
    - Отсутствует постоянный мониторинг — регулярный пересмотр и обновление мер по защите конфиденциальности для адаптации к новым угрозам и изменениям в среде обработки данных.
    - Не проводится моделирование угроз, выявление потенциальных уязвимостей и планирование мер противодействия.
    - Политики и процедур конфиденциальности отсутствуют.
2. Конфиденциальность по умолчанию
    - Не обеспечена Минимизация данных(собирать нужно только те данные, которые необходимы для достижения поставленной цели)  собирается всё возможное.
    - По умолчанию запрашивается полный доступ спектр конфиденциальных данных, вместо выполнения требования, что системы должны быть настроены таким образом, чтобы по умолчанию были включены наиболее благоприятные для конфиденциальности опции.
    + Выполняется частично. Точно неизвестно о применении Механизмы оптинга (требовать явное согласие пользователя перед сбором или обработкой персональных данных), вероятно, что  при заполнении анкеты данное согласие запрашивается сразу на все манипуляции и получаемые данные.
3. Конфиденциальность, не заложенная в дизайн 
    - Отсутствуют интегрированные меры безопасности , нет методов шифрования, анонимизации и псевдонимизации в процессах обработки данных.
    - Не применяются паттерны проектирования, поддерживающих конфиденциальность (например, безопасных потоков данных и модульной архитектуры).
    - Отсутвуюет управление жизненным циклом, не анализируется учёт влияния конфиденциальности на всех этапах жизненного цикла системы, от разработки до вывода из эксплуатации.
4. Полная функциональность без компромиссов
    - Отсутствие решения вопросов безопасности в пользу простоты информационной системы.
5. Комплексная безопасность 
    - не организовано Безопасное хранение без использования шифрования и контроля доступа для данных, хранящихся на серверах и в базах данных.
    - отсутствует безопасная передача черезвнедрение безопасных протоколов связи (например, TLS/SSL) для данных, находящихся в пути.
    - Нет утилизации данных, не разработаны процедуры безопасного удаления или анонимизации данных, которые больше не нужны.
6. Наглядность и прозрачность
    - Ввиду отсутствия, нет и публикации чётких и доступных политик конфиденциальности;
    - Отсутвие возможностей контроля у пользователей предоставлением доступа к их данным и возможности управлять настройками конфиденциальности;
    - Нет проверяемости, так как не внедрены процессы протоколирования и мониторинга для проведения аудита практики обработки данных.
7. Уважение к конфиденциальности пользователей
    - нет возможность дифференцированного применения механизмов согласия — получение информированного согласия пользователей перед сбором или обработкой их данных, так как все данные обрабатываются одновременно.
    - Отсутствует интерфейсов, позволяющий пользователям управлять настройками конфиденциальности.
    - Не реализуема отзывчивая поддержка — каналы для пользователей, по которым они могут задавать вопросы или высказывать опасения по поводу своей конфиденциальности, так как конфиденциальность пользовательских данных ничем не обеспечена.

#### **Data Minimization** не выполняется. 
 - Отсутвуют ограничения в доступе к данным со стороны внутренних пользователе.
#### **Least Privilege** не выполняется. 
 - Нет ограничений по привилегиям .
#### **Data Lineage** отсутствует. 
 - Нет как документирование процесса, так и возможности отслеживания происхождения и модификации данных.
#### **Методов защиты данных** (обфускации, маскировка, шифрование).
 - Ни один из методов ее применяется.

### Список проблемных зон (продублировано в problems.md).

1. Отсутствие категорирования и разделения данных.
2. Со стороны систем обработки нет ограничений на доступ к данным.
3. Совместно обрабатывает персональные, медицинские, финансовые данные и общие  документы.
4. Любой бизнес-процесс в компании сопровождается обращением к конфиденциальным данным разного уровня.
5. Общий отчёты по имеющимся данным могут содержать чувствительные необезличенные персональные и финансовые данные.

6. Пользователи не ограничены в правах доступа к информации за пределами своих служебных обязанностей.

7. Данные ничем не защищены и лежат в открытом виде.
8. Данные бесконтролько дублируются на рабочих местах пользователей.
9. Каналы связи ничем не защищены.

10. Внутренние потоки данных между IT-продуктами никак не контролируются. 
11. Не определить источник тех или иных данных
12. IT-системах нет аудита действий с данными.

13. Выход данных за пределы информационной системы не контроллирутся и не ограничивается.

14. Данные целенаправленно не резервируются, нет гарантии, что при утере найдётся где-то случайно сохранившаяся копия.
15. Отсутвуют средства и процедуры гарантированного удаления информации и прекращения обработки персональных данных (критично при отзыве согласия или истечения срока разрешения на обработку ПДн).

| 2 | **ПДн (расширенные):** адрес прописки, место работы/учёбы |**Обязательно** — то же, что в п. 1 |Референтные данные (адреса, организации) заменяются токенами в непривилегированных системах |В тестовых средах и логах |В отчётах — оставить только регион/населённый пункт |Полный адрес виден только уполномоченным (медсестра, регистратура, курьер); остальным — город/регион |

### Тегирование данных с использованием инструментов тегирования.

| № | Тег |Тип обрабатываемой информации | Пример |
|---|---|---|---|
| 1 |  PII_BASE |**ПДн** | Ф. И. О., дата рождения, телефон, e-mail |
| 2 |  PII_EXT  |**ПДн (расширенные)** | адрес прописки, место работы/учёбы |
| 3 |  PHI      | **Медицинские данные (особо защитимая категория ПДн)**  |диагнозы, анализы, назначения, история болезни, заключения, записи |
| 4 |  FINANCE  | **Финансовые данные** |оплаты, договоры, история платежей, зарплата, кадровые, налоговые |
| 5 |  INVENT   |**Учётные данные ТМЦ** | оборудование на складе, инвентаризационыне данные 
| 6 |  REP_LAKE |**Промежуточные данные для отчётов** | Подготовленные данные для получения отчётов |

Первичное автоматизрованное тегирование по имеющимся файловым ресурсам дальнейший контроль периметра можно реализовать применением DLP InfoWatch Traffic Monitor, для хранения и управления применять OpenMetadata.

### Список инструментов, способов и мер, которые позволят обеспечить конфиденциальность данных в указанных потоках.

| Поток | Меры и инструменты |
|---|---|
| **Ввод данных в систему** (администраторы, кассиры, врачи) | Формы с проверкой и минимизацией полей. Ввод только через системы с RBAC. Использование DLP InfoWatch Traffic Monitor c запретом копирования тэгированных данных ПДн на поключаемые usb-носители и передачи во внешние каналы (мессенджеры, почта). |
| **Хранение данных в системе** | Шифрование локальных станций BitLocker. Миграция серверного хранения из файлов на защищённую СУБД Jatoba с разграничением доступа; шифрованием данных и автоматическим тегированием при загрузке. |
| **Хранение данныхв 1С** | Переход на 1С с использованием защищённой СУБД Jatoba с шифрованием данных и ролевым доступом. |
| **Сетевое взаимодействие** (между компонентами системы, серверами 1С и ККМ, внешними взаимодействиями) | TLS 1.2+ для всех каналов. VPN для взимодействия с лабораторией. Передача только необходимых полей для заимодействия по API (Data Minimization). |
| **Обработка** (приложения, отчёты) | Разграничения RBAC/ABAC по тегам; маскирование ПДн при доступе ролей без необходимых прав к данным; журналирование обращений к тегированным данным. |
| **Подготовка отчётов** | RBAC/ABAC по тегам. Маскирование ПДн в отчётах. Журналирование обращений к тегированным данным. Шифрование промежуточных баз. |
| **Аудит и мониторинг** | Централизованное логирование доступа к данным с тегами PII_BASE, PII_EXT, PHI, FINANCE. Контроль и оповещение о массовое извлечении данных, нетипичных шаблонах поведения. Регулярная верификация и пересмотр прав доступа. |
| **Прекращение обработки и удаление данных** | Разработка регламента обработки запросов прекращение обработки ПДн. Обеспечение гарантировнного удаления или анонимизации данных по идентификатору пациента.Реализация журналирования событий удаления даных в журнале. |
